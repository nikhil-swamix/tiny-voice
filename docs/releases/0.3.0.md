# Tiny Voice 0.3.0

## Highlights

- **Local-first dictation.** Default formatting now runs on the existing local SGLang server with `minicpm5-2b-fp8`. The OpenAI formatter remains an optional comparator profile.
- **GPT Transcribe is off by default.** The finalized Nemotron CPU transcript is used, so the default pipeline uploads no audio and needs no OpenAI key. Enable GPT Transcribe in Settings when higher recognition accuracy matters.
- **Editable formatting prompt.** The formatter instructions are no longer hard-coded. Edit them in Settings, save them as `formatting-prompt.txt`, or restore the built-in default. The strict YAML schema stays native.
- **Readable YAML output.** New entries are proper shallow YAML: plain keys where safe, quoted single-line values, and literal block scalars for multi-line text. Exact YAML is copied and pasted.
- **Faithful dictation replaces task enrichment.** Quick/Pro modes, generated titles, hints, checks, word-count targets and task execution are removed.

## What changed since 0.2.0

### Recognition and formatting pipeline

- Replaced Deepgram live captions and Parakeet batch-final recognition with cached Nemotron Speech Streaming English 0.6B Q8_0 inference on strict CPU through transcribe.cpp.
- Added optional OpenAI `gpt-transcribe` refinement of the original saved WebM. The live preview is never sent as an authoritative transcript or script.
- Changed the default refinement behavior: GPT Transcribe is **off**. The finalized local transcript goes directly to formatting.
- Added a default local SGLang profile at `http://127.0.0.1:30000/v1` using `minicpm5-2b-fp8`, temperature zero and `enable_thinking: false`.
- Retained OpenAI `gpt-6.1-sol` at low reasoning as an explicit optional profile. Neither profile silently falls back to the other, and local formatting never requires a cloud key.
- Removed the old Quick/Pro output modes and enrichment behavior. A refused or incomplete provider response is reported; raw audio and transcript remain, and an existing output is kept if reprocessing fails.

### Output contract

- Replaced the previous task-note/Markdown enrichment with faithful cleanup and a strict logical-field response.
- New output is YAML with at most two mapping levels: a root leaf, or a root group with string-valued children. No arrays, third level, Markdown fences or commentary inside fields.
- Keys are nonempty and unique per mapping. Safe plain keys such as `project` or `owner` are emitted directly; ambiguous or reserved keys are quoted.
- Single-line values are double quoted so strings such as `true`, `123`, `# comment` or `null` cannot change type.
- Multi-line values use `|2-` literal block scalars when safe, preserving indentation and line breaks. Values with CRLF, trailing spaces, tabs or ambiguous control characters fall back to an escaped quoted scalar.
- The prompt prefers 3–5 root fields when the speech contains that many distinct facts, one field per fact, and never invents fields to reach a count. Continuous prose remains one `text` leaf.
- Exact YAML is copied and pasted. Legacy history entries remain readable as Markdown; new history entries record `output_format`, and the history viewer accepts `{text, output_format}` while still accepting legacy strings.

### Editable prompt

- Moved the formatter instructions to `src-tauri/prompts/formatting.txt` and embedded them as the built-in default.
- Added **Formatting prompt** to Settings with Save and Restore default controls.
- Custom prompts are stored as `formatting-prompt.txt` in the recordings folder. Empty, oversized (over 20,000 bytes) or control-character-containing prompts are rejected. An invalid saved file is ignored in favor of the default and the editor reports why.
- The strict JSON schema and native YAML validation are not editable, so a prompt change cannot bypass shape, key or value validation.
- Prompt edits apply to the next recording.

### Settings and privacy

- Defaults are now local SGLang/MiniCPM5, GPT Transcribe off, GPT-6.1 Sol/low only for the optional cloud profile, images off, English (India).
- Settings exposes the profile, loopback endpoint and local model, cloud model/reasoning, GPT transcription language, GPT Transcribe switch and prompt editor.
- The local profile is text-only; screenshots are disabled while it is selected.
- With local formatting and GPT Transcribe off, no audio or transcript leaves the machine. Enabling GPT Transcribe uploads original audio. Choosing OpenAI formatting sends transcript and bounded context, plus screenshots if enabled, even when GPT Transcribe is off.
- History compaction uses the selected profile. Local rebuilds fold bounded source fragments instead of depending on a cloud key. The previous summary and changed/new entries are used for incremental updates. Only the summary cache is replaced.

### Context, vocabulary and wording

- Formatting uses a compact voice-workflow summary plus observed vocabulary and contextual spelling hints, with fewer than 500 history-derived words total. The summary is capped at 350 words.
- Vocabulary comes from saved raw speech, not generated output. Correction candidates are scoped and are never global replacements.
- Removed obsolete Deepgram credentials usage, live-caption accuracy tiers, mandatory titles/labels/checks and historical enrichment instructions. Existing Deepgram credentials remain untouched but unused.

### Widget, history and delivery

- Fixed the widget to a 360-logical-pixel width with explicit compact/expanded views; no content-driven resize or hover expansion.
- Added the one-minute visual progress guide while keeping the ten-minute/20 MB safety limits.
- Kept focus-safe paste: the recording start target is checked before insertion, and insertion is skipped rather than activating another window. The final text is still copied.
- Added history output-format metadata and YAML-aware rendering while preserving old `.quick.md`/`.pro.md` reads.
- Added measured per-recording transcription and formatting times. When GPT Transcribe is off, the transcription time is the final CPU stream drain, not the full live streaming duration. Stage sums exclude capture, compaction and persistence.
- Added request audits without transcript text or credentials.

## Upgrade notes

- Existing recordings, history, preferences, API keys and consolidated text are preserved.
- Existing preference files with GPT Transcribe explicitly enabled keep that choice. Delete `preferences.json` or turn the switch off to use the new default.
- The local SGLang server and model are not bundled, started or downloaded. Run them separately at the configured loopback endpoint.
- Nemotron weights are not bundled or downloaded. The app expects Handy's cached `nemotron-speech-streaming-en-0.6b-Q8_0.gguf`; ffmpeg must be on `PATH`.
- Old history remains Markdown; new entries are YAML. The copy button copies exactly what is shown, without adding Markdown fences.
- Installer upgrades retain the per-user data directory.

## Requirements and limits

Windows 10/11 x64, microphone permission, WebView2, ffmpeg and Handy's cached Nemotron weights. Default local formatting additionally requires the SGLang server and `minicpm5-2b-fp8`. GPT Transcribe and the OpenAI formatter require internet and your own OpenAI API key with model access. The installer is unsigned. Recognition with GPT Transcribe off is less accurate than GPT Transcribe and may preserve local recognition errors. Local formatting quality is model-dependent; the default prompt can be edited, but the YAML schema cannot.

## Verification

- Native tests cover prompt validation, YAML key/scalar safety, block scalars, shape/depth rejection, local request conversion and history budgeting.
- Release build and NSIS installer were produced from this source.
- Smoke checks exercised the installed Settings prompt editor, local SGLang formatting, YAML history rendering and exact clipboard copy.
- A 20.87-second sample on one machine produced three GPT Transcribe results at 1.15–1.20 s, three local MiniCPM5 formats at 0.65–1.07 s and three Sol/low formats at 2.81–2.98 s. These are not general performance guarantees; the local formatter retained one spoken self-correction during review, so its cleanup is not identical to Sol.
